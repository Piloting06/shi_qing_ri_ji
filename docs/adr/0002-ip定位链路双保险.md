# ADR-0002: IP 定位链路——服务端透传真实 IP + 客户端直连兜底

日期：2026-08-28 ｜ 状态：Accepted ｜ 决定人：AI 提出，用户批准（scope.md）

## 背景

线上 `/api/weather/location` 返回的永远是服务器所在城市（杭州）：服务端在服务器上直接请求 ip-api.com，未传客户端 IP，ip-api 解析的是服务器出口 IP。叠加首页"GPS → 缓存 → IP"的兜底顺序，错误坐标一旦写入缓存即永久粘住。

## 备选评估

1. **仅修服务端**（透传 X-Forwarded-For）：依赖 nginx 正确配置转发头；历史上 nginx 配置不在我们掌控流程内，存在单点配置风险。
2. **仅客户端直连 ip-api**：不依赖服务端与转发头，但国内直连可用性无 SLA，且城迹页当时已深耦合服务端接口。
3. **双保险**（选定）：服务端从 `X-Forwarded-For`/`X-Real-IP` 取真实 IP 传给 ip-api（**IP 必须放在路径 `/json/{ip}`，查询参数 `?ip=` 会被忽略**——已踩坑）；内网/回环 IP 返回未知而非误定位；同时城迹页改为客户端直连 ip-api 兜底。

## 决策

选 3。注意两个不变量：ip-api 调用必须走路径传 IP；定位缓存版本号 `loc_cache_ver` 在改定位逻辑时必须递增（污染缓存整体失效）。

## 后果

- 收益：外网验证返回请求方真实城市（实测北京/南昌）；nginx 未转发头时返回未知而非杭州误定位；单接口故障不致全链路失准。
- 代价：客户端直连 http 明文（ip-api 免费档不支持 https），信息暴露面极小（仅 IP 查询）；两处实现需同步维护。
- 重评触发：ip-api 免费档配额/可用性出问题，或引入付费定位服务时。
