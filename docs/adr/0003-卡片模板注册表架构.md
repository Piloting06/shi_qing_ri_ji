# ADR-0003: 卡片模板采用「数据包 + 注册表」架构

日期：2026-08-29 ｜ 状态：Accepted ｜ 决定人：AI 提出，用户批准方向（scope.md：差异化主打分享卡片）

## 背景

初版 4 套卡片主题是配色变体，if/else 散在 `mood_card_maker.dart` 单文件（1195 行）。差异化战略确立"分享卡片是产品灵魂"后，模板将持续高频增加（12 套 → 年度报告卡等），原结构每次加模板都在改核心文件。

## 备选评估

1. **继续在 maker 内分支扩展**：改动集中、冲突面大、模板间无隔离，maker 必然超 2000 行。
2. **抽象基类 + 子类继承**：Flutter 组合优于继承；模板差异在"绘制方式"而非"行为契约"，继承层级收益低。
3. **数据包 + 无状态 builder + 注册表**（选定）：`MoodCardData` 承载全部可编辑内容；每套模板是纯函数 `Widget Function(MoodCardData)`；注册表 `mood_card_registry.dart` 集中元数据（id/名称/色点/label）。

## 决策

选 3。不变量：

- 新增模板 = 新 builder 文件 + 注册表加一条 `MoodCardTemplateSpec`，不改 maker 逻辑。
- 模板必须响应 `data.height`（竖版 216 / 方图自适应）与 `data.bodyScale`（正文字号档位）。
- 模板不得自行请求权限、不得内嵌手势（导出走 RepaintBoundary 截图，交互在外层）。
- 晴收集的天气用户覆盖（`_weatherOverride`）是明确的产品决定（scope.md 2026-08-31），不得移除。

## 后果

- 收益：v2.6→v2.8 三轮新增 8 套模板零核心改动；模板可独立调整；PageView 滑动切换天然成立。
- 代价：数据包字段是模板能力上界，新特效需求（如动态元素）需扩展 MoodCardData；注册表是单点清单，遗漏注册即模板不可见（analyze 不报错，需人工核对）。
- 重评触发：模板需要交互/动画能力，或出现按用户动态生成模板的需求时。
